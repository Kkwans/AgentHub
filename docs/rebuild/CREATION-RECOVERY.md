# 创建幂等与刷新恢复合同

## 范围

本切片只保证带 `operationId` 的 Task **创建**幂等。READY 转换、启动 Agent、返工与 Run 不被这个编号自动覆盖。旧客户端不携带编号时仍按原接口创建。

## 服务端

- `POST /api/v1/tasks` 可选 UUID `operationId`。服务端从已认证主体取得范围：浏览器账户使用稳定 accountId；API token 使用 tokenId；本地信任模式使用部署内固定范围。客户端不能指定范围。bootstrap token 的固定标识和 local_trusted 不能当成独立个人账户。
- 同一范围和编号全局唯一，不把项目放进唯一键。同编号更换项目或创建语义返回 `409 TASK_OPERATION_PAYLOAD_MISMATCH`。
- hash 使用校验后创建语义、稳定键顺序与缺省值；UUID大小写和十进制位置规范化。hash 不含operationId本身，不含启动变量，也不在日志记录正文。
- 同一数据库事务竞争操作账本主键，写 Task、固定版本 Prompt binding、操作对应Task ID；任一步失败整体回滚。使用 `ON CONFLICT DO NOTHING`，不在唯一冲突后继续使用已失效事务。
- 已提交重放先读取原结果，不因Prompt后来归档/标签移动重新选择版本。首次Prompt解析在事务外，绑定写入原子不等于与资产归档强串行隔离。
- `GET /api/v1/tasks/creation-operations/:operationId` 仅按当前主体范围查找，返回operationId/projectId/taskId/status/sessionId，设置no-store，不返回正文、hash或变量。
- **404仅表示当前没有已提交记录，不证明原请求未执行或不在途。** 请求内容还在内存时，可以同编号、同内容重试；不得从404自动换新编号。

## 迁移与清理

增量迁移0006建立操作账本；保留已有Task/Prompt/版本。账本通过外键约束已有项目/Task，拒绝自动级联清理。原人工项目清空脚本显式在同一项目范围内先清账本再删Task，并警告该行为撤销幂等历史。开发/测试没有执行对用户数据的清空操作。

## 浏览器恢复（后续接入，不冒称本切片已完成）

1. 首次请求前生成编号，保存最小恢复线索：编号、项目、已确认账户范围、阶段、可选Task ID。
2. 不保存任务正文、Prompt变量、cookie、token或认证材料。每个操作独立存储键，避免多标签覆盖同一数组。
3. 只读取当前已确认账户和项目的线索；身份未知不猜测范围，切换账户立即撤销旧操作展示/导航所有权。
4. 刷新/重开后只查询结果。找到Task/Session则提供原任务或Workspace入口，不自动续发start。READY且sessionId为空仍不能证明没有在途Session创建。
5. 存储不可用、损坏线索、未知响应、404均显示边界；不能伪装已保存、已失败或已安全取消。当前内存同编号可重试和跨刷新仅查询应明确区分。
6. UI需覆盖关闭/取消、导航切换、跨账号、双击、迟到响应与存储事件；恢复不授予原本没有的项目权限。

## 验证边界

实际PGlite/HTTP测试覆盖同编号并发、不同内容冲突、跨身份查询隔离、同账户跨登录、UUID规范化、Prompt归档后的重放、事务回滚、正文不进入错误日志、旧客户端兼容；迁移覆盖旧库升级、关闭重开、重复迁移及旧中文/emoji数据保留。人工reset仅验证计划/顺序，不执行真实清空。

尚未覆盖真实PostgreSQL多连接竞争；不能用PGlite单进程结果声称多进程实测。未来项目级权限必须同时作用于新建、重放和恢复路径。身份范围变更、数据库重置及明确清除账本后不能保证原编号跨范围去重。

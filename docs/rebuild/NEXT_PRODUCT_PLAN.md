## 五个既有内置 Agent 的真实联调台账

证据等级分别记：源码通路 / mock 合约 / 真实服务加替身 / 真实 Provider / 目标 NAS。等级不能互相替代。以下“待验收”指当前基线，不抹去历史记录，也不把历史单次成功直接搬作当前成功。

`CUSTOM_ACP` 是自定义协议扩展入口，不是第六家已验证 Agent。每个矩阵单元须填写：commit、OS/架构、target、CLI/adapter/model 版本、开始结束时间、用例结果、日志位置、剩余限制。敏感凭据不得写入台账。

通用用例：注册→预检→新会话→流式文本→工具调用→批准/拒绝→取消确认→同会话继续→断连/重连→关闭/恢复→进程重启→认证/配额/网络失败。未知结果只核对，不自动重放可能已生效的指令。未支持的能力显示“不支持”，不伪造成功。

## Agent 管理生命周期的分片设计

1. 预检 UI：现有 preflight 即使 smokeSession=false 也启动 ACP 进程并 initialize，写入 Agent 状态/时间，READY 时更新能力；Docker 还可能按策略启动容器。不能标为“只读”或“不启动 Agent”。第一片先限定已验证 LOCAL_HOST ACP、显式工作目录和固定非 smoke，披露副作用；项目/目标约束需服务端 projectId/expectedTargetId 校验，不能只靠前端。完整检测报告当前未持久化，超时无法只读复原全部结果，不自动重投。后续 smoke 检测另说明可能创建会话与费用。
2. 配置编辑：现有默认 model/mode 保持读回核对；新增名称、目标等字段前明确是否允许在运行中变更。引入版本或等效冲突保护，不能覆盖另一页面的新值。
3. 禁用/启用：只控制新准入；运行中的会话单独列出，不暗中取消。
4. 运行进程停止：有确认/未知状态，依赖各 adapter 权威停止能力；失败保留归属，不把关闭 UI 当停止 Agent。
5. 移除：先引用与运行检查，再可恢复的移除策略；不删除 Session/Run/Approval 审计记录，不级联毁历史。

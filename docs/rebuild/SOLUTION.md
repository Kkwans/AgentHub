# 详细技术与产品方案

## 1. 目标与取舍

第一目标是普通用户不用理解内部实体即可完成：选择项目 → 确认可用 Agent → 描述工作 → 执行/批准 → 审阅修改 → 完成。第二目标是有设计感、稳定而流畅的桌面工作台，手机能够查看、批准、停止、审阅，不硬挤四栏。

保留 TypeScript 单体及数据库契约，原因是现有适配生态、测试与数据模型可复用。重构重点放在工作流编排、状态归属和 UI。若后续真实 profile 证明框架或存储阻碍目标，再单独 ADR 比较迁移成本、兼容与回滚，不凭主观厌恶换栈。

## 2. 工作创建与恢复协议

- 任务创建成功是独立持久结果；Agent 启动失败不能抹去该结果。
- 明确阶段：draft / creating / created / starting / running / start_failed / outcome_unknown。
- UI 保存服务器返回的 taskId，错误时展示“任务已创建，启动失败”及查看任务/恢复启动，不重新 POST create。
- 服务端启动需要任务级单次受理和状态条件更新；为 clientRequestId 建持久幂等边界时同时定义请求摘要、保留期、冲突响应，不用纯前端按钮禁用冒充幂等。
- 保存用户主目标、补充说明、验收标准，不相互替代。初始 Run 与返工输入应采用同一可测试的上下文构造器。
- 新建任务所选 Prompt 必须生成显式任务绑定或一次性已解析上下文，采用固定版本/内容哈希并存来源；绝不只做 URL 装饰。变量缺失先显示可修复表单。

## 3. 项目与 Agent 就绪

项目选择展示本机/节点、允许根、目录面包屑、仓库候选、Git/写入/Agent 可用性；目录跳转每次都由服务端 containment 校验。Agent 的“已安装”“已注册”“可启动”“需登录”“不可用”分开，READY 不能覆盖最新诊断失败。昂贵发现由用户动作或受控缓存触发，普通列表不反复执行完整扫描。

## 4. 设计系统与信息架构

采用克制的工程工作台：中性灰底、明确层级、少量品牌强调色、真实状态色；不靠大面积渐变、玻璃卡片或数据卡墙营造精致。统一字号、字重、行高、8px 间距体系、圆角、边框、阴影、图标尺寸与动效时长。浅深色分别检查对比度，系统减少动态效果生效。

- 左侧稳定项目/会话导航；主区域只突出当前工作及一个主要操作。
- 首页为继续工作、需要处理和开始入口，不堆领域统计。
- 工作台中心对话/任务进度，审阅区承载文件、Diff、Git；批准与停止始终可达；终端按需展开。
- 1024/768 下审阅区切换 tabs/drawer；390 下内容单列，避免遮挡输入和批准。
- 组件层只保留一套 Button/Input/Dialog/Menu/Tabs/Status/Empty/Error/Loading；逐页迁移而非增加第三套样式。
- 每个页面必须定义 loading/empty/error/partial/stale/disconnected 状态，错误有具体恢复动作。
- 先截图审查当前真实页面，再实现关键首页/项目/Workspace 的视觉样板，以实际浏览器验证后扩散。

## 5. 后端与实时连接

把 SessionService 逐步拆成 SessionLifecycle、RunCoordinator、ApprovalDelivery、Configuration、Continuation 等内部服务，领域类型不依赖协议供应商。每次拆分先保留行为回归。

统一认证主体标识与撤销事件：HTTP、WS、PTY 绑定同一主体；注销/改密/撤销必须停止旧连接，连接建立与撤销竞争也要覆盖。不记录 token 原文；历史事件补流再次校验有效性，输出与重放有容量边界。

## 6. 验证与交付

分四级证据：单元/fixture → 本地真实服务 HTTP/浏览器 → 真实 Agent → NAS。每一级独立标记，不能互相替代。

每切片 lint/typecheck/test/build；涉及流程需故障注入、连点、取消、返回、重连、重启；UI 需 1440/1024/768/390 的实际页面截图、console/pageerror、溢出和关键交互。CI 补 real-service 门禁，不在普通 CI 调用付费 Agent。

保留现有 API 和数据，迁移有前向/回滚说明；禁止重置用户数据库。开发分支逐切片提交，main 合并与实际部署单独作为最终门禁，不能把“同 NCP 工作方式”推导为自动部署许可。

# 隔离审阅差异行层级

## 证据与目标

2026-11-14 03:03 UTC实际查看b293537真实CI的1440/390图。文件/patch已前置，但整块同色文本无法快速识别新增、删除和hunk边界。目标是接近已选Codex审阅层级，不改变审阅内容或安全许可。

## 实现边界

- unified diff进入hunk后才将前导+/-标记为新增/删除；---/+++文件头仍为上下文。新文件头重置hunk状态。
- 普通React文本span，不解析HTML、不渲染Markdown；空行、CRLF和无末尾换行逐字保留。原始+/-符号保留，颜色不是唯一提示。
- 复用双主题success/accent软背景。CR发现danger前景配浅红背景只有4.409:1，删除行用主文字色和浅红背景，避免改动全局token。
- 仅128Ki字符以内且不超过2000行着色。超限直接完整原始字符串，绝不截断或宣称没有改动。useMemo缓存行节点，表单输入不重复解析大patch。
- 保持region名称、tabIndex、320px滚动区、默认展开、折叠/重开、所有确认与UNKNOWN保护；不改Git、API、队列和合并流程。

## 验证与执行

- 单测：逐字保真/文件头区分/二进制不猜测；大patch无逐行DOM且编辑说明不丢原文/自动确认。
- 真实四宽retry沿用精确patch.textContent，新增新增行/hunk相对正文颜色断言，保留真实Git、折叠重开及无额外POST断言。
- types/lint/build/独立CR/最终冻结全量后commit&push。最终真实截图仍须精确新CI获取；旧图仅为问题证据。
- 当前不新增复杂代码编辑器、语法高亮依赖或DOM行号。删除/新增保持补丁原文，避免显示转换制造审阅误解。

# AgentHub v0.2 Worktree Task Runner 轻量 SDD

## 目标

在现有 Project → Task → Agent → Session → Run → Review 闭环上增加持久队列、隔离
worktree、任务分支和显式 merge gate，同时保持现有直接运行入口可用。

## 范围

### 本切片包含

- Worktree Execution 状态机、数据库表、repository 与恢复规则；
- 每 Project 单并发 FIFO 队列；
- Git worktree 创建、状态/Diff、受管提交、merge preflight 与 `--no-ff` merge；
- Agent Session/Run 编排、Approval 等待状态、继续修改和取消；
- `/api/v1/worktree-executions` 与 Task queue 入口；
- 中文 Task 看板中的隔离执行、队列/运行/审阅/合并状态与错误反馈；
- 单元、API、Git 集成和浏览器 E2E 测试。

### 本切片不包含

- 自动删除 worktree/分支；
- 自动 push、PR、rebase、force push、自动解决 merge conflict；
- 跨 Project 并发配额和多 Agent swarm；
- Remote Node 上的 worktree。Remote Node 在下一切片把相同领域契约下沉到 Node。

## 公共契约

```ts
type WorktreeExecutionStatus =
  | 'QUEUED'
  | 'SETTING_UP'
  | 'RUNNING'
  | 'AWAITING_INPUT'
  | 'REVIEW'
  | 'MERGING'
  | 'DONE'
  | 'BLOCKED'
  | 'CANCELED';
```

```text
GET  /api/v1/worktree-executions?projectId=&taskId=&status=
GET  /api/v1/worktree-executions/:id
GET  /api/v1/worktree-executions/:id/review
POST /api/v1/tasks/:id/worktree/queue
POST /api/v1/worktree-executions/:id/rework
POST /api/v1/worktree-executions/:id/merge
POST /api/v1/worktree-executions/:id/cancel
```

Queue body：

```ts
{
  agentId: string;
  baseBranch?: string;
  model?: string;
  mode?: string;
  promptVariables?: Record<string, unknown>;
}
```

Merge body：

```ts
{ commitMessage?: string }
```

所有错误使用稳定英文 code；用户信息使用中文。原始 Git stderr 只进入脱敏调试日志，
不进入默认响应。

## 数据与不变量

- `worktree_executions.task_id/project_id/agent_id` 为显式可查询列；模型、模式和 Prompt
  变量存放于受限 `config_json`，不得含供应商登录凭据。
- 保存 `base_branch/base_sha/task_branch/worktree_path/session_id/run_id/merge_commit_sha`、
  时间戳与稳定错误信息。
- partial unique index 阻止同一 Task 或 Project 出现多个活跃 Execution。
- repository 使用带当前状态条件的更新，竞争失败返回 `WORKTREE_EXECUTION_CONCURRENT_UPDATE`。
- 不可由数据库自动级联删除 Project、Task、Session 或 worktree 文件。

## 队列与恢复

1. Queue 前验证 Task=`READY`、Project=`GIT`、Project target 非 `REMOTE_NODE`、Agent 可用；
2. 记录当前 base branch/SHA，事务创建 Execution 并把 Task 置为 `IN_PROGRESS`；
3. 调度器按 `queued_at, id` FIFO 获取 Project 的首项；
4. `SETTING_UP` 创建隔离 worktree；`RUNNING` 创建 Session 并启动 Run；
5. Run 完成进入 `REVIEW`；等待 Approval 时进入 `AWAITING_INPUT`；
6. server restart：保留 `QUEUED`；其他非终态标为 `BLOCKED`，保留现场并要求人工恢复；
7. 一个 Execution 进入终态后再调度同 Project 下一项。

## Merge gate

1. Review 数据必须成功读取，且 Execution=`REVIEW`；
2. 主工作区 clean 且当前分支等于 `base_branch`；
3. `base_sha` 仍是当前 base branch 的祖先；
4. task branch 与 worktree 身份匹配；
5. 用户明确提交 merge 请求；
6. 隔离工作区有未提交变更时执行 `git add -A` 和单一受管 commit；
7. 通过无冲突 preflight 后执行 `git merge --no-ff --no-edit <task-branch>`；
8. 成功后记录 merge SHA 并完成 Task；失败则 abort 并回到 Review。

## 安全与回滚

- `/usr/bin/git` 绝对路径、argv、`shell: false`、输出上限和超时；
- 只在显式 managed root 下创建 worktree；不接受客户端路径；
- 不执行 `worktree remove`、branch delete、reset、rebase、force push 或清理；
- DB 迁移向前追加；应用回退时新表和磁盘 worktree 保留；
- merge 后的业务回滚使用新 revert commit，由用户显式操作。

## 验收标准

- 两个同 Project Task 按 FIFO 执行，第二项在第一项审阅/合并前保持 `QUEUED`；
- Session cwd 为 managed worktree，任务分支与数据库一致；
- Run 完成只进入 Review，不自动 merge；
- dirty 主工作区、错误分支、base 历史被替换或冲突时拒绝 merge；
- merge 成功后 Task/Execution 为 DONE，主分支包含受管 commit，worktree/分支仍存在；
- traversal、symlink escape、非法 ref 和并发状态更新测试均被阻止；
- v0.1 直接 Task Run 回归通过。
